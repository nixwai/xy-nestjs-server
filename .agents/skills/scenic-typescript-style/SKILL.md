# 景区预约平台 TypeScript 编码规范

## 类型与模块

- 保持 `strict: true`，为公开函数、Service 方法、配置对象和响应结构声明明确类型。
- 避免无意义的 `any`、类型断言和隐式可空值；外部数据先校验再使用。
- 遵循项目 ESM 规范：本地 TypeScript 导入使用实际运行时需要的 `.js` 后缀。
- 仅使用当前 `tsconfig.json` 已配置的路径解析方式，不假设未配置的 `@/` 别名存在。
- 使用 `index.ts` 暴露稳定公共 API；不要通过桶文件导出内部实现造成循环依赖。

## 不可变性与函数设计

- 优先创建新对象、数组和返回值，不直接修改调用方持有的对象。
- 纯逻辑提取到 `src/common/utils/<功能>.util.ts`，导出命名函数；新增前先检查是否已有可复用工具。
- 函数保持单一职责，优先减少嵌套和隐式副作用；不要为了满足行数而拆出难以理解的碎片函数。
- 不在 Controller 中堆积领域逻辑，不在 Entity 或 DTO 中执行副作用。

## 注释与命名

- 类、公开方法、DTO、Entity、配置接口和复杂业务分支使用简洁中文 JSDoc，说明真实用途、参数和返回值。
- 注释只解释当前代码行为，不保留迭代历史、猜测性设计或与实现不一致的承诺。
- 命名使用清晰的领域中性术语。
- 类型、接口、枚举和类使用 PascalCase；变量、方法和属性使用 camelCase；文件和目录使用 kebab-case。

## 错误处理

- 不静默吞掉错误；必须显式处理、记录必要上下文或向统一异常边界抛出。
- 不在客户端错误中返回内部异常对象、堆栈、SQL、路径、令牌或配置内容。
- 异步调用必须处理失败路径，避免未处理 Promise；遵循 Oxlint 配置。

## 工具链与复杂度

- 修改 TypeScript 后遵循项目 Prettier 和 Oxlint 配置，不引入新的格式化或 Lint 体系。
- 函数通常控制在 50 行以内，文件通常控制在 800 行以内，嵌套通常不超过 4 层；超出时先确认职责是否需要拆分。
- 修改注释、类型或导出时同步检查调用方、测试和 OpenAPI 生成结果。
- 完成修改后执行 `pnpm typecheck`、`pnpm lint`、相关测试和 `pnpm build`。
