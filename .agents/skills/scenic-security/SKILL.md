# 景区预约平台安全规范

## 密钥与配置

- JWT 密钥、数据库密码、COS SecretId/SecretKey、微信 AppSecret 和其他凭据只能通过运行时环境变量注入。
- 禁止在源码、YAML、测试样例、日志和提交内容中写入真实凭据或弱默认密钥。
- JWT 密钥缺失或不满足校验要求时必须启动失败，不得静默使用默认值。
- 业务模块通过 `ConfigService` 读取配置，不直接读取 `process.env`。
- 生产环境禁止 TypeORM `synchronize`；数据库结构变更必须经过审查的 Migration。

## 认证与授权

- JWT 使用项目配置中的密钥，并强制校验过期时间，不能设置 `ignoreExpiration: true`。
- Token 从 `Authorization: Bearer <token>` 提取，缺失、格式错误或无效时按统一认证错误处理。
- 认证、授权和资源归属检查必须在请求边界或领域服务中明确执行，不能仅依赖前端隐藏按钮。
- 新增敏感接口时检查身份、角色、资源所有权、审计和限流要求；未经确认不得发明角色或权限模型。

## HTTP 与输入安全

- 应用保持 Helmet 安全响应头、受控 CORS 和全局严格 ValidationPipe。
- 所有外部输入必须通过 DTO 和 `class-validator` 校验；拒绝未声明字段，限制字符串、数字、数组和分页参数范围。
- 对数据库使用参数化的 TypeORM API 或 QueryBuilder 参数，不拼接未经校验的 SQL。
- 文件、媒体和外部 URL 等输入必须按实际业务约束校验；未确认约束不得放宽为任意内容。
- 通过限流守卫保护登录、验证码、上传和高成本接口；限流配置从配置模块读取。

## 错误与日志

- 客户端错误消息不得泄露堆栈、SQL、文件路径、密钥、令牌或基础设施细节。
- 服务端日志记录必要上下文，但不得记录密码、完整 Token、Secret 或其他敏感载荷。
- 对认证失败、权限失败、输入异常和高风险操作保留可审计的信息，但遵循最小化原则。

## 提交前检查

- 检查硬编码凭据、调试日志、敏感响应字段和不受控外部输入。
- 检查新增接口是否有认证、授权、校验和限流边界。
- 检查生产配置是否仍然关闭 `synchronize`，测试是否可能连接真实数据库。
