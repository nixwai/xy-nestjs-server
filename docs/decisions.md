# 技术决策

## Vitest 替代 Jest

需求文档建议 Jest，但当前项目脚手架已经使用 Vitest。为减少测试体系迁移并保持现有基线，本项目正式采用 Vitest + Supertest；后续测试文档、CI 和 Agent 规范均以 Vitest 为准。

## 单一 YAML + 环境变量

删除环境专用 YAML，保留唯一的 `config/config.yaml` 作为完整配置模板和稳定默认值。开发、测试和生产差异由环境文件与运行时环境变量控制，配置加载、类型转换和校验由统一入口完成。

该方案避免基础 YAML、环境 YAML 和 `process.env` 三套来源同时覆盖同一字段，同时保留 YAML 对嵌套配置的可读性。

## 环境隔离

开发环境允许使用本地 `.env.development.local`。测试环境只读取 `.env.test.local` 和 `.env.test`，不回退读取开发配置；测试始终关闭真实数据库。生产环境只使用 CloudBase 注入的运行时变量。

## 测试不连接数据库

基础工程测试不依赖外部 MySQL。数据库模块根据统一配置构建结果决定是否加载，生产和开发的数据库就绪状态通过健康检查暴露。

## 关联完整性由应用层维护

项目数据库不创建外键和级联约束。关联表保留业务 ID、唯一索引和查询索引，由应用服务在写入前校验关联主体，并在同一事务边界内完成关系变更。该方案降低模块、数据库和未来服务拆分之间的耦合；数据库结构仍通过迁移管理，关系字段命名和索引必须保持明确。


## 动态授权模型

系统采用业务权限编码驱动的动态 RBAC：权限编码由代码注册，管理员与角色、角色与权限的关系由数据库维护。接口通过 `RequirePermission` 声明业务能力，通过 `Authenticated` 声明登录要求，通过 `RootOnly` 声明不可委派的系统管理边界。HTTP 方法不参与权限编码。

菜单使用权限编码控制可见性，前端按钮应复用同一权限编码；前端展示不构成安全边界，后端 Guard 和业务服务必须继续校验权限。受保护权限不能绑定给普通角色，避免通过角色配置实现自我提权。

## 权限目录的分组维护

权限定义在代码中按分类分组声明，分组是唯一的编辑入口，运行时消费铺平后的注册表，仓储、实体和数据库结构不感知分组。分类标识使用稳定的小写英文值写入数据库，展示名称和展示顺序由分类目录单独维护；权限编码统一为 `<分类>.<资源>.<动作>`，首段必须等于所在分组分类。

启动同步只补齐代码维护的定义字段，权限启用状态由数据库保存且不被代码覆盖；代码中移除的权限不会自动删除数据库记录，废弃通过显式迁移处理。路由声明的权限编码与注册表由测试双向校验，避免出现永久拒绝访问的路由和无人使用的权限条目。权限目录接口按分类分组返回，分组结果由数据库数据与分类元数据合成，不直接返回代码常量，以免与数据库真实状态不一致。

## 菜单核心结构与展示配置分离

菜单核心结构由后端注册表以嵌套 `children` 数组维护，层级由结构本身表达，`menuKey`、路径、权限编码和根管理员边界在定义处声明；数据库按扁平化结果保存，父级以 `parent_key` 绑定。数据库记录以及可编辑的标题、排序和启用状态由管理端维护。图标由前端根据 `menuKey` 映射，不进入后端菜单表。

服务启动只补齐注册表中缺失的菜单，不覆盖已有展示配置、不恢复停用菜单、不删除未知记录。注册表扁平化后启动校验仅覆盖 `menuKey` 唯一性和菜单引用的权限编码存在（允许权限停用）；父菜单缺失和循环父级在嵌套结构下不可能出现，无需校验；无权限叶子菜单允许存在。同时校验数据库与注册表的结构字段和未知 `menuKey`，发现不一致时阻止启动，结构变更通过 TypeORM Migration 发布。

菜单管理仅允许根管理员修改标题、排序和启用状态，删除和动态创建接口不提供。菜单停用使用 `isActive`，不再维护 `deletedAt`。菜单仅负责导航可见性，后端 API 仍由 RBAC Guard 独立鉴权。
